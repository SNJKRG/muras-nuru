# Критерии приёмки реализации

Это будущие проверки агента. Наличие чек-листа не означает, что сайт уже реализован или протестирован.

- Присутствуют 16 содержательных сценариев, шапка и футер; нет сокращения до нескольких generic-блоков. Недостающий журнал стройки получает честное компактное состояние, а не фальшивые даты.
- Canvas и поверхности #FFFFFF. Нет бежевых полей, глобального noise, неуместных градиентов и декоративных сфер.
- Desktop hero соблюдает «текст слева, горы справа, дома ниже». Три главные вершины свободны, текст и действия не перекрываются. Есть этап и проектная подпись.
- Арт сохраняет крупные гуашевые пятна, естественные лица, alpha и ограниченную палитру. Фасады, планы и логотипы не подменены генеративным board.
- Реальные screenshot-ы всей страницы: 1440, 1280, 1024, 768, 390, 360, 320 px. Проверить именно готовую страницу и состояния, а не только код. Отчёт содержит доступные браузеры и реальные ограничения.
- Обычный контент без горизонтальной прокрутки при 320 px; план имеет отдельный доступный увеличенный просмотр. Заголовки не сжаты до мелкого текста, основная строка ограничена.
- Проверить keyboard: Tab/Shift+Tab, Enter/Space, Escape; focus видим; закрытие модального слоя возвращает focus, скрытые элементы не принимают Tab.
- Контраст обычного текста ≥4,5:1, крупного ≥3:1. Золото только декор. Выбранность и ошибки не только цветом. Цель 48×48 — проектный выбор; не выдавать её за формальный минимум WCAG.
- На mobile все основные действия доступны без hover; форма работает с клавиатурой; панели учитывают safe-area; нет маленького плюсика как единственной цели.
- Проверить Noto на русской и кыргызской строках, в том числе «Өмүр, үй, жаңы». Сохранять OFL рядом с font files. Перевод и переключатель языка не выдумывать.
- Планировки: этапы различаются; обе площади подписаны; цена неизвестна, а не ноль; наличие unknown не значит доступно. Проверить сброс пустого фильтра, потерю/сохранение контекста, большой план.
- Форму проверить реальным endpoint: local error, loading, success, server error, повтор без потери ввода. Без endpoint явно demo. Контактная панель не имитирует онлайн-менеджера.
- Открываются все три PDF; этап, страницы и размер совпадают с файлом. Они не загружаются сами при первом заходе.
- Карта и маршруты проверены отдельно для объекта и офиса; нет выдуманных минут и непроверенного пина.
- Reduced motion: статичный орёл, мгновенные функциональные изменения, без плавной прокрутки. Обычный режим не содержит scroll hijacking и автопоявления каждого текста.
- Safari и мобильный Safari проверить на alpha, sticky, overlay, высоту при клавиатуре, фильтры, форму; Chrome и Firefox отдельно. Если браузер недоступен, назвать это.
- Предложенный бюджет первого входа ≤2 МБ передачи, hero mobile ≤450 КБ медиа. Это цели подготовки, не измеренные результаты. Пересмотреть размер изображений по реальному качеству и метрикам.
- Цели [Core Web Vitals](https://web.dev/articles/vitals): LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1 на 75-м процентиле реального трафика отдельно mobile/desktop. Лабораторную проверку не выдавать за эти полевые метрики.
- Все числовые продажи, сроки, адреса и документы соответствуют этапу, имеют актуальный источник. Неподтверждённые claims не публикуются.
- После существенной итерации краткая таблица: элемент → задача → решение → основание → компромисс → как проверено. Без обещаний конверсии на основании статичного просмотра.

Основания: [W3C Contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Конкретная сетка, порядок секций, размер 48 px и медиабюджеты — решения проекта, а не универсальные стандарты.
